# MW OAuth v1.1: Google clients, application tokens and refresh

This summarises the contract consumers integrate against. The full API
reference is updated in the release phase.

## What changed from v1

- The long-lived project API key (`mw_live_...`) is **removed**. There is no
  rotate-key admin route and no `api_key` in the project-creation response.
  Applications authenticate only with MW client credentials (below).
- Every project brings **its own Google OAuth client**, stored encrypted. There
  is no shared global Google client and no `GOOGLE_CLIENT_ID` /
  `GOOGLE_CLIENT_SECRET` setting.
- Applications authenticate with an **MW client ID and secret**, exchanged for a
  900-second access token. The token is sent as `Authorization: Bearer mw_at_...`.
- MW OAuth can **renew Google access tokens**, so the consumer no longer needs
  the Google client secret to refresh.
- The signed success callback carries a `credential_ref`.

## 1. Get an access token

```http
POST /v1/auth/token
Authorization: Basic base64(<mw_client_id>:<mw_client_secret>)
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&scope=google.authorize google.refresh
```

```json
{ "access_token": "mw_at_...", "token_type": "Bearer", "expires_in": 900,
  "scope": "google.authorize google.refresh" }
```

Credentials must be sent with HTTP Basic, never in the URL or the body. `scope`
is optional (default: everything the client may be granted). Errors follow RFC
6749: `invalid_client` (401), `invalid_scope`, `invalid_request`,
`unsupported_grant_type`, `unauthorized_client` (403, disabled client or
project), `rate_limited` (429, honour `Retry-After`).

## 2. Authorize a user

`POST /v1/oauth/google/authorize` with `Authorization: Bearer mw_at_...`
(scope `google.authorize`) and the same body as in v1. The project's active
Google client is chosen and **pinned to the authorization**: rotating the
credential while the user is on Google's consent screen does not change which
client exchanges the code.

Extra errors: `409 google_client_missing` (the project has no active Google
client), `503 google_client_unavailable` (the stored client cannot be used).

## 3. The signed callback

The signed callback body gains one field:

```json
{ "event": "oauth.authorization.completed", "transaction_id": "...",
  "client_reference": "...", "provider": "google",
  "credential_ref": "gcred_...", "token": { "access_token": "...",
  "refresh_token": "...", "token_type": "Bearer", "expires_in": 3599, "scope": [] } }
```

Store `credential_ref` **next to the Google refresh token**. The signature input
(`delivery_id.timestamp.raw_body`) is unchanged and covers `credential_ref`.

## 4. Refresh a Google access token

```http
POST /v1/oauth/google/refresh
Authorization: Bearer mw_at_...        (scope google.refresh)
Content-Type: application/json

{ "credential_ref": "gcred_...", "refresh_token": "<google refresh token>" }
```

```json
{ "access_token": "ya29...", "token_type": "Bearer", "expires_in": 3599,
  "scope": ["https://www.googleapis.com/auth/calendar.events.readonly"] }
```

`refresh_token` appears in the response **only if Google issued a replacement**;
replace the stored one atomically only then. MW OAuth stores no user tokens.

| Status | `error.code` | Meaning and action |
|---|---|---|
| 401 | `invalid_token` | Token missing, expired or revoked: get a new one and retry. |
| 403 | `insufficient_scope` | The token lacks `google.refresh`. |
| 403 | `project_disabled`, `client_disabled`, `provider_disabled` | Operator action needed. |
| 404 | `credential_not_found` | Unknown `credential_ref`, or not this project's. |
| 409 | `credential_unavailable` | The Google client was disabled, deleted or is unusable. Operator action, or reauthorize. |
| 409 | `reauthorization_required` | Google says the refresh token is dead. Mark the connection as needing consent and stop retrying. |
| 429 | `rate_limited` | Honour `Retry-After`. |
| 502 | `provider_unavailable` | Google unreachable. Retry with backoff. |
| 503 | `provider_rate_limited` | Google is throttling. Honour `Retry-After`. |
| 400 | `invalid_request` | Fix the request. |

Use the exact `credential_ref` the authorization returned. A refresh token only
works with the Google client that issued it, so a rotated-out client keeps
refreshing the tokens it issued until the operator disables it.

## Consumer guidance

- Keep the Google refresh token encrypted, together with its `credential_ref`.
- Cache access tokens until shortly before they expire.
- Serialize refreshes per connection.
- On `reauthorization_required`, do not retry: ask the user to connect again.
- Keep MW and Google secrets out of browsers, URLs and logs.
